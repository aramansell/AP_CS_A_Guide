FRQ 4: 2D Array

6 points. A grid, a traversal, a twist. Your dungeon maps, battle grids, and fog of war are this question's native habitat. The two-part structure is common: part A traverses and computes, part B writes or transforms the grid with bounds awareness.

Round A: Fog of War (6 points)

A dungeon is an int[][] grid of 0s and 1s (1 = wall, 0 = floor). The player stands at (pr, pc). Visibility rules: a cell is visible when it is within 2 cells of the player in BOTH row and column (Chebyshev-style box), AND not a wall.

Part A (3 points):

/** Returns the number of visible cells, not counting the player's
 *  own cell.
 */
public int countVisible(int[][] grid, int pr, int pc)

Part B (3 points):

/** Marks the grid: sets every visible cell to 2 (keep walls as 1).
 *  Returns nothing.
 */
public void revealFog(int[][] grid, int pr, int pc)

Part A Solution

public int countVisible(int[][] grid, int pr, int pc) {
    int count = 0;
    for (int r = Math.max(0, pr - 2); r <= Math.min(grid.length - 1, pr + 2); r++) {
        for (int c = Math.max(0, pc - 2); c <= Math.min(grid[r].length - 1, pc + 2); c++) {
            if (grid[r][c] == 0 && !(r == pr && c == pc)) {
                count++;
            }
        }
    }
    return count;
}

Commentary: Math.max(0, pr-2) and Math.min(bound, pr+2) are the box-with-bounds idiom in one line. If you find them hard to read, write the four separate ifs instead: both earn. The player's own cell exclusion is the rubric's sneaky row: "not counting the player's own cell" must survive to your code.

Part B Solution

public void revealFog(int[][] grid, int pr, int pc) {
    for (int r = Math.max(0, pr - 2); r <= Math.min(grid.length - 1, pr + 2); r++) {
        for (int c = Math.max(0, pc - 2); c <= Math.min(grid[r].length - 1, pc + 2); c++) {
            if (grid[r][c] == 0) {
                grid[r][c] = 2;
            }
        }
    }
}

Commentary: same box, different verb. Walls stay 1 because the if guards the write. Notice part B does NOT exclude the player cell: the spec did not say to. Spec-literalism is the skill: do exactly what is written, no more, no less. Adding your own flourishes (like excluding the player here) is how strong students lose points inventing rules.

Rubric (6 points)

PointEarned by
1Nested traversal bounded correctly (rows and columns both)
2The +/-2 box restricted to the grid (no out-of-bounds reads)
3Part A: correct count with player-cell exclusion and wall filter
4Part B: writes to grid cells (mutation, not a copy)
5Part B: walls untouched (guard before write)
6Both methods use bounds-safe iteration with jagged rows (grid[r].length)

Round B: Fireball Grid (mock material)

An arena is int[][] arena, each cell an elevation 0-9. A fireball lands at (fr, fc) with radius R (int).

/** Part A: returns the total elevation of all cells within
 *  Chebyshev distance R of (fr, fc), excluding walls (-1 elevation).
 */
public int scorchTotal(int[][] arena, int fr, int fc, int R)

/** Part B: sets every cell in the radius to 0 UNLESS its elevation
 *  is 9 (obsidian, fireproof). Returns the number of cells changed.
 */
public int castFireball(int[][] arena, int fr, int fc, int R)

Boundary training: fireball at the corner with R=3 (most of the box is off-grid), a wall-only region (total 0, changed 0), and the obsidian exception in B. Trace a 5x5 by hand before the mock. If your hand-trace and your code disagree, one of them is lying, and the exam pays you to know which.

The FRQ 4 Repertoire

Every grid question is built from the 2d-algorithms catalog: row/column walks, box traversal with bounds, neighbor counts, find-and-where, and transform-in-place. The five methods of 8.6's tinker challenge are literally a practice exam for this FRQ. If you did them, you have already written the hard parts.

Drill List

  • Write the Math.max/Math.min box bounds from memory, then the four-separate-ifs version. Know both.
  • Jagged rows: grid[r].length, never a width constant. Say it three times.
  • Trace fog of war on a 5x5 with the player at (0,0). Count by hand. The corner is where bounds bugs live.
