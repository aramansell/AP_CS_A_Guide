FRQ 2: Class Design

7 points, one class, built from a spec table. You did this every Tuesday for a month in Phase 3, and again in 5.6a. The exam's version has one twist you must train: a second small class sometimes appears, and one method must USE an object of it. Composition, not inheritance.

Round A: The Spell Class (7 points)

A game tracks spells. Each Spell has a name, a mana cost, and a damage value. A Mage class already exists with getMana() returning the mage's current mana.

Write the entire Spell class:

Constructor: Spell(String name, int manaCost, int damage)

int getManaCost()           returns the mana cost
int getDamage()             returns the damage
boolean canCast(Mage m)     true when m's mana is at least the cost
String toString()           "Fireball [30 mana, 25 dmg]"

Solution

public class Spell {
    private String name;
    private int manaCost;
    private int damage;

    public Spell(String name, int manaCost, int damage) {
        this.name = name;
        this.manaCost = manaCost;
        this.damage = damage;
    }

    public int getManaCost() { return manaCost; }
    public int getDamage()   { return damage; }

    public boolean canCast(Mage m) {
        return m.getMana() >= manaCost;
    }

    public String toString() {
        return name + " [" + manaCost + " mana, " + damage + " dmg]";
    }
}

Rubric (7 points)

PointEarned by
1All private instance variables declared (3)
2Constructor: correct signature, all fields assigned
3getManaCost correct
4getDamage correct
5canCast: calls m.getMana() (using the object, not re-implementing) and compares with >=
6toString: correct concatenation and format
7Class compiles: braces, semicolons, headers exact

Commentary: point 5 is the real test. "At least" means >=. Using the Mage parameter's method instead of imagining the mana is the composition skill. Point 7 is free for careful writers: slow down for 30 seconds at the end and collect it.

Round B: The Mount Class (mock material)

A Mount has a name, a speed (int, 1-10), and a stamina (int, 0-100). A Rider class exists with getWeight().

Constructor: Mount(String name, int speed, int stamina)

int getSpeed()                  the speed
void rest(int hours)            adds hours * 10 stamina, capped at 100
boolean canCarry(Rider r)       true when stamina is at least 20 and
                                speed exceeds the rider's weight / 10
String toString()               "Shadowfax (speed 9, stamina 85)"

Boundary tests the rubric will use: rest pushing past 100, stamina exactly 20, weight exactly speed * 10. Bring your boundary checklist.

The Spec-Writing Eye (train both directions)

5.6a made you write specs for classmates. Do it again with Mount: cover the spec, write your own version from memory, then compare. Every difference is either your ambiguity or your blind spot. Both are worth finding before May.
