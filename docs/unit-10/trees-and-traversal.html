Trees & Recursive Traversal

Beyond the exam, deep in Season 2. A tree is a structure made of nodes where each node points to children. You have been living in one all year without noticing: your call stack during recursion IS a tree being walked. Trees are where recursion stops being a technique and becomes a worldview.

The Binary Tree, In One Class

public class TreeNode {
    int value;
    TreeNode left;
    TreeNode right;

    TreeNode(int v) { value = v; }
}

That is the whole structure. A tree is a node with two smaller trees hanging off it. The recursive definition is the data structure. Compare with your GameCharacter plans: objects referencing objects, all the way down.

The Three Walks

public static void inorder(TreeNode node) {
    if (node == null) return;          // base case: empty subtree
    inorder(node.left);                // walk left subtree
    System.out.print(node.value + " ");// visit this node
    inorder(node.right);               // walk right subtree
}

The only difference is WHERE the visit line sits. Move one line, change the entire walk. Trace a 7-node tree by hand with all three and the point lands permanently.

Size and Depth: The Standard Recurrences

public static int size(TreeNode node) {
    if (node == null) return 0;
    return 1 + size(node.left) + size(node.right);
}

public static int depth(TreeNode node) {
    if (node == null) return 0;
    return 1 + Math.max(depth(node.left), depth(node.right));
}

Every tree method you will ever write has this shape: null base case, combine the children's answers. The recursion does the walking; you write the combining rule. That division of labor is why tree code is so short.

Decision Trees: Dialog Engine Mini-Build

The Talking Goblin

Build a dialog tree for a goblin merchant. Node = one line of dialog plus up to two choices (left/right). Then a recursive converse(node): print the line, if there are choices ask the player 1 or 2, recurse into the chosen child, else end. Twenty lines of code, and your RPG now has branching conversations that a writer can grow without touching the engine. The tree structure decouples content from code, exactly like maps-from-files decoupled levels from code.

Why Trees Are Beyond the Exam but Not Beyond You

The CED's recursion topic (4.16-4.17) covers recursive methods on numbers, strings, and arrays, plus binary search and merge sort. Trees are not required. But notice what you just did: you understood trees in ten minutes, because recursive thinking is recursive thinking. The exam teaches the thinking; the trees are what the thinking buys in the wider world: databases, file systems, compilers, game AI, your own save-file structure. Season 2 exists for exactly this kind of payoff.

Socratic Checkpoint

Why is inorder of a binary SEARCH tree sorted?

A BST stores smaller values left and larger values right. Inorder visits left (all smaller), then self, then right (all larger). So every value is printed after everything smaller and before everything larger: the definition of sorted. The walk and the invariant cooperate. That is the same cooperation as binary search's "it is always in [lo, hi]."

Why is depth's base case 0 and not -1 or 1?

Convention: an empty tree has depth 0, a single node has depth 1. The choice must make the recurrence true: depth = 1 + max(children), and a leaf's children are null (0), so leaf depth = 1. Check the arithmetic at the boundary you care about, then stay consistent. Base cases are definitions, not guesses.
