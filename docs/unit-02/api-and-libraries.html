APIs & Libraries

You have never written a random number generator. You have never written a string searcher. You never will. Java shipped with all of it, and you have been calling that code since your first week. Today we name what you have been doing, because the exam names it too, and because the skill of reading someone else's interface is the skill of a working programmer.

The Vocabulary

TermMeansExample you already used
LibraryA collection of prewritten code, shipped with the language or by a publisher java.util.Scanner, java.lang.Math
API (Application Programming Interface) The public contract of a library: what you can call, what you pass, what comes backint length() is API. The code inside length() is not. It is hidden and you do not need it.
PackageA named folder of classes java.util holds Scanner, ArrayList, Random
ImportThe line that makes a package's classes usable by nameimport java.util.Scanner;
DocumentationThe written form of the API The JQR. Oracle's javadoc pages. Your Dice.java's javadoc comments.
The mental model: a library is a vending machine. The API is the button panel. You read the panel, you press, you get. You never open the machine. Abstraction means the panel is all you need.

java.lang: The Free Library

Classes in java.lang (Math, String, System, Integer) are auto-imported. That is why you have never written import java.lang.Math;. Everything else needs the import line:

import java.util.Scanner;        // keyboard and file input
import java.util.ArrayList;      // the resizable list
import java.io.File;             // the file handle (Unit 7.6)

Static vs Instance: Two Kinds of Buttons

Static (class) methodInstance method
Called onThe class nameAn object
ExampleMath.abs(-5)name.length()
Needs an object first?NoYes, one must exist
WhyThe answer does not depend on any object's state The answer depends on THIS object's data

Math.abs(-5) is the same no matter what, so it hangs on the class. name.length() depends entirely on which String you hold, so it lives inside each String object. When you read a signature on the JQR, the word static tells you which kind of button you are pressing.

Reading javadoc Like an Adult

Oracle publishes the full Java API documentation online. The layout of every page is the same, forever:

  1. Signature line: modifiers, return type, name, parameters
  2. Description: what it promises, in prose
  3. @param entries: each input, described
  4. @return: the output contract
  5. Throws: what can go wrong

That structure is generated from the /** */ comments you write in 2.8b. Your javadoc comments and Oracle's documentation are the same technology. When you document your Dice class, you are publishing an API for your future self.

Tinker Challenge: Hunt in the Real Docs

Find a Method You Have Never Used

Open the official Java API docs for String (search "Java 17 String javadoc"). Rules of the hunt:

  1. Find one method not on the JQR and not used in this course.
  2. Read its signature and description until you can explain it in one sentence of plain English.
  3. Demo it in a tiny program: a call, an output, a comment saying what it did.
  4. Find a second one that would help the RPG. Propose it in two sentences.

The skill being trained: cold-read an unfamiliar API entry and act on it. Every job you will ever have starts with exactly this.

Socratic Checkpoint

Why is the API the contract and not the code?

Because callers depend on the promise, not the implementation. Oracle can rewrite the inside of Math.random() entirely (they have) and no program breaks, as long as the promise "0.0 up to 1.0" holds. Interfaces that hide implementation are what make software replaceable, upgradeable, and team- buildable.

Why does the exam give you a method sheet at all?

Because memorizing signatures is not programming. Reading a contract and implementing against it is. The sheet's existence is College Board telling you what they think the skill is. Believe them, and train the reading speed.
