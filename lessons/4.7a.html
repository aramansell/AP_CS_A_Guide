4.7a — How Fast Does It Run? (Informal Run-Time Analysis)

Discovery Lab ~40 min

Every algorithm you have written has a cost. Today you learn to price them. Not with a stopwatch: with structure. The AP exam tests this as "informal run-time analysis" and it is the doorway to the searching and sorting questions that dominate the data-collections unit. You already own every piece of intuition you need. You built them in the dungeon.

Experiment 1: Count the Steps, Watch the Shape

Create SpeedLab.java:

// A: sum an array by visiting every element once
int sum = 0;
for (int i = 0; i < n; i++) sum += data[i];        // n steps

// B: sum by nested loops (silly, but legal)
int sum2 = 0;
for (int i = 0; i < n; i++)
    for (int j = 0; j < n; j++)
        sum2 += (i == j) ? data[i] : 0;             // n * n steps

Build both with n = 10, print the sums to confirm they match, and count steps with a counter variable (add steps++ inside each loop body). Record step counts for n = 10, 100, 1000. Make a table in your notes. The A column: what happens when n grows 10x? The B column: what happens? One of them grows like a straight line. The other does something much worse.

The vocabulary, earned: Algorithm A does about n steps. We call that linear ("grows like a line"). Doubling n doubles the work. Algorithm B does about n-squared steps. We call that quadratic. Doubling n QUADRUPLES the work. That is the whole difference, and it is the difference between "runs in a second" and "heat death of the universe before the second dungeon loads."

Experiment 2: Price Your Own Dungeon

Go back to your Unit 4 dungeon crawl. Find and price these:

  1. The room loop that prints 5 rooms (linear in rooms)
  2. Your ASCII dungeon map printer from 4.4c: nested loops over rows and columns. If the map is r rows by c columns, how many print operations? (r * c. Linear in area.)
  3. The "search every room for the key" pattern: rooms inside a traversal of floors. What shape is that?

Write your prices in your notes. Then the big question: your map printer handles a 9x9 map instantly. What about 1000x1000? Same algorithm, one million prints. Does it finish? (Try it. Time it. Feel the quadratic wall.)

Experiment 3: Linear Search Gets a Price Tag

You wrote linear search in Unit 6 (check each element until found). Price it: n elements, worst case n steps. Best case 1 (the target is first). Average n/2. All are "about n". Now, this is the setup for the punchline you get in Phase 4: binary search on sorted data does about log n steps. You do not need the math yet. You need the feeling: log n means "cut the remaining search in half every step." Watch it happen:

int lo = 0, hi = n - 1, steps = 0;
while (lo <= hi) {
    steps++;
    int mid = (lo + hi) / 2;
    System.out.println("step " + steps + ": checking index " + mid);
    if (data[mid] == target) break;
    else if (data[mid] < target) lo = mid + 1;
    else hi = mid - 1;
}
System.out.println("total steps: " + steps);

Run it on a sorted array of 1000 elements with target at the end. Count the steps. Now run linear search on the same array with the same target. Put both numbers in your table. THAT gap, 10 steps vs 1000, is why the rest of the course exists.

Socratic Checkpoint

  1. Algorithm A is linear, algorithm B is quadratic. Both are "correct." When would you actually choose B? (Trick question: almost never, but "when n is tiny and B is much simpler to write" is a real answer.)
  2. A loop that runs n times containing another loop that runs n times is quadratic. What about a loop that runs n times containing a loop that runs 10 times (a constant)? Linear or quadratic? Why does the constant not matter at scale?
  3. Predict: selection sort, which you meet in 7.3, uses nested loops over the list. Linear or quadratic? When you get there, come back and check your prediction.

Checkpoint — before moving on, you must be able to:

  • Count steps with a counter and tabulate growth as n scales
  • Classify a loop structure as linear or quadratic on sight
  • Explain why constants fade and shapes dominate at scale
  • State the step counts of linear vs binary search and why they differ
