7.5a — Deduplication & Frequency: Duplicates, Counts, and the Cost of Naive Solutions

Discovery Lab ~20 min

You know how to add, remove, and search an ArrayList. But real programs face harder questions: "Does this list have duplicates?" "Which item appears most often?" "How do I remove repeats without losing order?" These problems expose the true cost of your data structure choices.

Part 1: Has Duplicates?

Write a method that answers one question: does this ArrayList contain any duplicate values?

public static boolean hasDuplicates(ArrayList<String> list)

Test it:

["apple", "banana", "apple", "cherry"] → true
["apple", "banana", "cherry"] → false
[] → false
["apple", "apple", "apple"] → true

Socratic Checkpoint

You wrote hasDuplicates. Now: how MANY comparisons does your code make for a list of size N? If N=10, about how many? If N=100? If N=1,000,000? Write your guess before reading further, then test it by counting comparisons with a counter variable.

Part 2: Remove Duplicates (Preserve Order)

Write a method that returns a NEW ArrayList with duplicates removed, preserving the original order. The first occurrence of each value is kept.

["dog", "cat", "dog", "bird", "cat"] → ["dog", "cat", "bird"]
["a", "b", "c"] → ["a", "b", "c"]
[] → []

Socratic Checkpoint

Approach A: For each element, scan everything before it. O(N²) comparisons. Approach B: Use a second ArrayList of "seen" values and check contains(). Still O(N²) if contains() scans. What would you need to make this O(N)? (Hint: what data structure does O(1) contains?)

Part 3: Frequency Counter

Write a method that counts how many times each unique string appears:

["cat", "dog", "cat", "bird", "cat", "dog"]
→ "cat": 3, "dog": 2, "bird": 1

Return type: two parallel ArrayLists — items and counts — where counts.get(i) is the count for items.get(i).

Tinker: RPG Loot Analyzer

Your adventurer has defeated 200 monsters. Each dropped one item — recorded in a large ArrayList of item names like "Potion", "Gold", "Sword", etc. Build a loot analyzer that shows:

  • Total unique item types
  • Most common drop (the "common" loot)
  • Any item that appeared exactly once (the "rare" loot)

Checkpoint — before moving on, you must be able to:

  • Detect duplicates in an ArrayList and explain the comparison cost
  • Remove duplicates while preserving insertion order
  • Build a frequency counter using parallel ArrayLists
  • Explain why certain algorithms are slow (O(N²)) and what would speed them up
