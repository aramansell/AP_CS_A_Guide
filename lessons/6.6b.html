6.6b — Data Sets: Clean, Aggregate, Answer

Expand Application ~40 min

Yesterday you answered questions about 30 players. Today you learn what happens when data is not so kind: missing fields, impossible values, rows that lie. Real datasets are messy on purpose. The workflow is always the same three moves: clean, aggregate, answer. Master it on 30 rows and you can run it on 30 million.

Part 1: The Messy File

Here is a slice of telemetry with problems added. Copy these lines into a String[] in MessyData.java:

player_id,class,level,session_minutes,gold,quit_flag
201,Wizard,5,60,120,0
202,Wizard,0,,90,1          // missing minutes
203,Warrior,-3,45,60,1      // negative level?
204,,7,80,200,0             // missing class
205,Mage,4,55,,-1           // missing gold, quit_flag -1?
206,Warrior,2,99999,10,0    // session longer than a day
207,Mage,6,70,150

Write a loader that processes every line and, for each row, classifies it as CLEAN or BAD with a reason. Rules for BAD: wrong field count, empty required field, negative level, session minutes over 1440, quit_flag not 0 or 1. Print a report: row id, CLEAN/BAD, reason. Count each kind of problem.

The pattern you just built has a name: guard clauses. Check field count, then check each field, and reject early with a reason. The same pattern guards your command parser from 2.2c and will guard your file loader in 7.6. Data cleaning is 60% of real data work. Congratulations, you are now employable.

Part 2: Aggregation Patterns

Back on the clean telemetry.csv data, build these four aggregations. Each is one loop plus one accumulator. These four patterns cover most of FRQ 3 forever:

  1. Total and mean: total gold across all players, then average gold. (Accumulate, then divide. Watch your int division! Cast to double first. Thank you, 1.8a.)
  2. Count by category: how many Warriors, Mages, Rogues? (One counter per category. Try it with parallel arrays now; when you meet ArrayList in three lessons, you will feel the upgrade.)
  3. Max/min and who: most gold and WHO holds it. You must track the value AND the index. Classic exam move.
  4. Conditional aggregate: average quests_done for players who did NOT quit. (Filter inside the loop: one accumulator plus one counter, both under the if.)

Bug Hunt: The Average That Wasn't

A student averaged session minutes for non-quitters like this:

int total = 0;
for (int i = 0; i < lines.length; i++) {
    if (quit[i] == 0) {
        total += minutes[i];
    }
}
double avg = total / lines.length;   // bug?

Two bugs. One is about which rows belong in the average. One is integer division. Find both, fix both, prove the fix with a hand count of 3 rows.

Socratic Checkpoint

  1. Your cleaning rules rejected session_minutes over 1440. Is 99999 minutes "bad data" or "a lie"? What is the difference between cleaning and censoring, and who decides the rules?
  2. Row 204 has an empty class field. Another student says "just fill it with Warrior, that's the most common." What is that called, and what danger does it hide? (Imputation. When is it OK, when is it fabrication?)
  3. Of the four aggregation patterns, which two showed up in your FRQ 3 practice? Check the FRQ 3 page if you do not remember. They will be back on the mock exam.

Checkpoint — before moving on, you must be able to:

  • Write guard clauses that reject bad rows with reasons
  • Build total/mean, count-by-category, max-and-who, and conditional aggregates
  • Spot the denominator bug and the int-division bug in an average
  • Explain imputation and its risks
