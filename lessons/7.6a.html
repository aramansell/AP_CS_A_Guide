7.6a — Reading Files: The Bestiary Loads Itself

Discovery Lab ~40 min

Every monster so far has been hardcoded into your Java. Today the bestiary moves out of the code and into a file. This is the moment your RPG becomes a real game: data separate from engine. Modders can add monsters without touching your code. Designers can rebalance without a recompile. And you get to use the two most beautiful words in the language: new File.

Download the data files first. Grab monsters.txt and items.txt and put them in the same folder as your .java files. (Right-click, Save As if the browser shows them as a page.) monsters.txt: name, hp, attack, gold, type, one monster per line. items.txt: name, weight, value, rarity.

Experiment 1: First Read

Create FileLab.java. You know Scanner from keyboard input. The only new idea: Scanner can wrap a File instead of System.in. Type this:

import java.util.Scanner;
import java.io.File;

Scanner fileScanner = new Scanner(new File("monsters.txt"));
while (fileScanner.hasNext()) {
    String line = fileScanner.nextLine();
    System.out.println(line);
}
fileScanner.close();

Run it. The whole bestiary prints. Six lines of code. Now the important question: what does hasNext() actually ask? Predict, then test: what happens if you call nextLine() one more time AFTER the loop ends? Uncomment a nextLine() after the loop and read the exception. Then put it back. The loop shape while (hasNext()) { nextLine(); } is "ask permission, then act." Memorize the shape; the exam expects you to write it cold.

The exception you cannot ignore: putting new Scanner(new File(...)) in main makes the compiler demand throws FileNotFoundException on the main signature. You will see public static void main(String[] args) throws FileNotFoundException all through this course. That is you telling Java "I know the file might not exist, I accept the consequences." Add it when the compiler asks. The exam gives you this for free in its starter code; in our class you write it yourself so it never looks strange.

Experiment 2: Split the Lines Into Data

Printing lines is for tourists. Combine with 2.9a: split each line, parse the numbers, and build Monster objects (your Unit 5 class). Structure:

ArrayList<Monster> bestiary = new ArrayList<Monster>();
while (fileScanner.hasNext()) {
    String line = fileScanner.nextLine();
    String[] f = line.split(" ");
    // f[0] name, f[1] hp, f[2] attack, f[3] gold, f[4] type
    Monster m = new Monster(f[0], Integer.parseInt(f[1]),
                            Integer.parseInt(f[2]), Integer.parseInt(f[3]));
    bestiary.add(m);
}
System.out.println("Loaded " + bestiary.size() + " monsters.");

Then answer with code: which monster has the most hp? What is the total gold value of the bestiary? Sort by attack and print the top 3 (your 7.3 selection sort, three weeks of foreshadowing paying off).

Bug Hunt: The Three Classic File Bugs

  1. The missing file: change the filename to "monsters.txtt" (extra t). Read the exception. Where does it say the file name? Where does it say the line of YOUR code that triggered it? Reading FileNotFoundExceptions is a job skill.
  2. The wrong delimiter: items.txt uses commas. Split it on a space by mistake and what happens? (Everything ends up in f[0] and f.length is 1. Then f[1] throws ArrayIndexOutOfBounds. Trace it.)
  3. The number that isn't: add a line to monsters.txt with "many" as the hp. parseInt throws. Catch it with a guard: check f.length == 5 first, and skip-and-report bad lines instead of crashing. Your 6.6b cleaning rules, now load-bearing.

Experiment 3: Save Games (the other direction)

Reading is half the loop. For saving we cheat with System.out redirection in your terminal:

$ java Game > save.txt

Print the player's name, hp, and gold in the same "name hp gold" format your loader expects. Close the loop: run the game, save, edit the save file by hand (give yourself a million gold, you earned it), load, verify the cheat worked. Data and engine, fully separated. You just made a save system.

Socratic Checkpoint

  1. Why is "data in files, engine in code" better than hardcoding? Give the modder argument and the designer argument, then the memory argument (what happens when you hardcode 10,000 monsters?).
  2. The JQR Scanner table lists hasNext(), not hasNextLine(). Look at both rows on the JQR. In our loop, we used hasNext() + nextLine() together. Why is that safe here, and when would mixing them bite you? (Hint: 8.6, reading maps char by char.)
  3. Telemetry.csv from 6.6 had a header row. Your monsters.txt does not. Where in your loader would you skip a header, and how do you detect a header without hardcoding "skip line 1"?

Checkpoint — before moving on, you must be able to:

  • Write the hasNext/nextLine loop from memory
  • Load a data file into ArrayLists of objects with split and parseInt
  • Diagnose FileNotFoundException, wrong-delimiter, and bad-number errors
  • Explain why data lives in files and engines live in code
