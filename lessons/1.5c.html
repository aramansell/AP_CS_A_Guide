1.5c — Tip Calculator: Bill Splitter & RPG Gold

Expand Application ~20 min

Your Tip Calculator handles one bill, one tip, one total. Real programs handle multiple inputs, split checks, and round to cents. And your RPG already has gold — the same arithmetic powers loot distribution.

Requirement 1: Split the Check

Add to your TipCalculator:

  • Declare a variable for the number of people splitting the bill
  • After computing the total (including tip), calculate each person's share
  • Display: "Each person pays: $X.XX"

Bug Hunt: The Rounding Trap

Run your split with: bill $100.00, 20% tip, 3 people. Each share is $120.00 ÷ 3 = $40.00. That divides evenly. Now try: bill $45.67, 18% tip, 4 people. What do you actually get vs. what you expect?

Java doubles don't divide money cleanly. Don't fix it — just observe it. You'll learn the proper fix (using integers for cents) in Unit 2.

Requirement 2: Service Rating

Instead of hard-coding the tip percentage, use a service rating system:

  • Poor service = 10%, Average = 15%, Great = 20%, Outstanding = 25%
  • Declare a variable for the rating — use it to set the tip percentage
  • Print the rating alongside the receipt

Socratic Checkpoint

  1. In the Slot Machine, you used Math.random(). In the Tip Calculator, you used arithmetic. In the RPG, you need BOTH. Where does each one appear? Can you explain why some problems need randomness and some don't?
  2. You've now seen three applications of the three-step pattern. What's the pattern behind the pattern? If you had to describe it to someone who's never coded, what would you say?

Requirement 3: RPG Gold — Party Split

Open a new file: GoldSplit.java. A party of 4 adventurers just defeated a dragon with 847 gold pieces.

  1. Declare the total gold
  2. Calculate each member's share (integer division is fine for now)
  3. Calculate the remainder — the coins that don't split evenly
  4. Print: "Each gets 211 gold. 3 coins remain (donate to the tavern)."

Tinker: Unequal Split

The fighter gets 40%, the rogue gets 30%, the cleric gets 20%, and the wizard gets 10% (they stayed in the back). Recalculate the split and print each member's share. Check: do all four shares add up to the total?

Checkpoint — before moving on, you must be able to:

  • Write a program that splits a value across multiple recipients
  • Use integer division and modulo to handle remainders
  • Apply the three-step pattern to a completely new problem — without being told where each step goes
  • Articulate what the three-step pattern IS — not just follow it, but explain it
