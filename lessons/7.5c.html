7.5c — Fisher-Yates Shuffle & Weighted Loot Drop

Expand Application ~25 min

Part 1: Fisher-Yates Shuffle

The algorithm that shuffles a deck of cards. In-place, O(N), and mathematically uniform — every permutation is equally likely.

Algorithm (work backward through the list):

  1. Start at the last index (i = size-1). Pick a random index j from 0 to i (inclusive).
  2. Swap elements at i and j.
  3. Move to i-1 and repeat until i=0.
Original: [A, B, C, D, E]
Shuffled: [C, A, E, B, D]
Shuffled: [B, E, A, D, C]  ← different every time
Shuffled: [A, B, C, D, E]  ← possible but rare (1/5! = 1/120)

Socratic Checkpoint

  1. Why j ranges from 0 to i (not 0 to size-1)? What would happen if you always picked from the entire list?
  2. Run your shuffle 1000 times on [1,2,3]. Count how often 3 ends up in each position. Are the counts roughly equal? Should they be?

Part 2: Weighted Random Select

You already built loot drops with if-else ranges (Unit 1). Now build a generic system: given an ArrayList of items and a parallel ArrayList of weights, return a random item where the probability of each item is proportional to its weight.

Items:   ["Common Sword", "Rare Axe", "Legendary Bow"]
Weights: [70,             25,         5]

Over 1000 drops:
  Common Sword:  ~700 times (70%)
  Rare Axe:      ~250 times (25%)
  Legendary Bow:  ~50 times (5%)

Algorithm:

  1. Compute the total weight (sum all weights)
  2. Pick a random number from 0 to total-1
  3. Walk through the weights, subtracting each from the random number
  4. When the number goes negative, that's the selected item

Bug Hunt: Zero-Weight Items

What if a weight is 0? What if ALL weights are 0? What if the random number lands exactly on an item boundary? Design test cases for each edge case and verify your code handles them gracefully.

Part 3: RPG Integration — Loot Table 2.0

Replace your old if-else loot system with a WeightedLootTable class:

  • Constructor takes two ArrayLists: items and weights
  • Method roll() returns a random item weighted by rarity
  • Method roll(int n) returns n random drops (with shuffling for variety)
  • Wire it into your combat loop: defeated monsters call lootTable.roll()

Tinker: Difficulty-Based Loot Tables

Create three loot tables — easy, medium, hard. Easy monsters use the easy table (mostly common drops). Boss monsters use the hard table (higher legendary chance). The player's inventory fills with different quality gear depending on what they fight. Prove the drop rates are correct by running 1000 simulations.

Checkpoint — before moving on to Unit 8, you must be able to:

  • Implement Fisher-Yates shuffle and explain why it's uniform
  • Build a weighted random selector from parallel ArrayLists
  • Handle edge cases: zero weights, empty lists, negative weights
  • Replace hard-coded if-else loot with a data-driven loot table
