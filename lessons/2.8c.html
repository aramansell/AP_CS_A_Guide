2.8c — Method Signatures: The Contract on One Line

Expand Application ~25 min

A method signature is the single line that defines a method: return type, name, parameter list. It is a contract. The JQR is nothing but signatures plus what they promise. Free-response questions hand you signatures and expect you to implement the contract. Today you read contracts, write contracts, and break contracts on purpose.

Experiment 1: Decode Six Signatures

No compiler. Decode each signature into plain English, out loud or in notes: what does it take, what does it give back, what words tell you it belongs to the class itself rather than an object?

public static int roll(int sides)
public static double max(double a, double b)
public int length()
public String substring(int from, int to)
public boolean equals(Object other)
public void close()

Check yourself against the signatures docs page. Then find all six on the JQR or in your own Dice.java. Yes, close() is on the exam sheet, Scanner class. You will use it for real in the file unit.

Experiment 2: Contract First, Code Second

Write these signatures into Dice.java FIRST, with empty bodies that just return 0; or return false;. Then implement each contract:

  • public static int damageRoll(int sides, int count) — rolls count dice of the given sides, returns the total. Reuse roll().
  • public static boolean isCrit(int roll, int sides) — true when roll equals sides.
  • public static String rarityLabel(int value) — "common" under 50 gold, "uncommon" under 200, "rare" under 1000, "epic" otherwise.

The discipline: the signature is written and committed before the body exists. This is exactly how FRQs present work to you: contract in the problem, body by you.

Bug Hunt: Break the Contract

In your tester, try each of these and read every error carefully. Each one violates the contract in a different way:

int r = Dice.roll("20");               // wrong parameter TYPE
int r2 = Dice.roll();                  // missing parameter
Dice.roll(20);                         // legal? what happens to the return value?
String s = Dice.roll(20);              // wrong return TYPE
double d = Dice.roll(20);              // legal? why?
int r3 = Dice.isCrit(20, 20);          // boolean into int

Write down which lines compile and which do not, and the exact reason. The line that compiles but ignores the answer is the most instructive: Java allows you to discard a return value. Silent, legal, and usually a bug.

Socratic Checkpoint

  1. public static void main(String[] args). Decode every word. You have typed this hundreds of times. Now you can read it.
  2. Two methods named attack in the same class: attack(String target) and attack(int damage). Legal or not? What is that called? (You met it in Unit 5 constructors: overloading.)
  3. On the exam you will sometimes be asked to WRITE the signature for a described method. Describe-to-signature is a two-way skill with signature-to-English. Write the signature for: "a static method that takes a String name and returns true if the name is a boss monster, false otherwise."

Checkpoint — before moving on, you must be able to:

  • Decode any signature into plain English: inputs, output, static or instance
  • Write a signature from an English description
  • Predict which contract violations compile and which do not
  • Implement a method from a signature-first spec
